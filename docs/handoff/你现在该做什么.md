# 你现在该做什么 —— 一步步来

按顺序做就行。**每一步都标了"要花多久"和"做不做得成会怎样"**,你可以随时停。

前三步加起来大约 **20 分钟**,而且不需要装任何东西。

---

## 第 1 步:下载两样东西(2 分钟)

打开右边的**下载页**(预览窗口),下载:

1. **`shuncode-bridge-source.zip`** —— Bridge 源码包
2. **`web_agent提示词-修正版-纯净.txt`** —— 给另一个助手的话

> ⚠️ 注意:页面上还有一份 `WEB_AGENT_HANDOVER.md`,里面也有提示词,
> **那份是旧的,别用**。用"修正版·纯净"那份。

---

## 第 2 步:转交给 web_agent 的助手(5 分钟)

打开你 web_agent 项目的会话,做两件事:

1. **上传** `shuncode-bridge-source.zip`
2. **粘贴** `web_agent提示词-修正版-纯净.txt` 的全部内容

就这样,不用你自己解释。提示词里已经写清楚了:

- 我们**不是**要整体替换他们的 MCP(那样风险高收益低)
- 只建议挑 **4 个模块**看:会话驱逐、自适应并发、信号量、id 登记
- 请他们**检查自家 `server.js` 有没有同一个 `string[]` 请求头缺陷**
- **"如果都不值得用,请直接说"**

> 💡 为什么这么保守?因为我读了他们的代码,他们的 MCP 服务端已经能跑,
> 而且和审批/审计体系绑在一起。整体替换更可能帮倒忙。
>
> 而且有一点要说清楚:**他们的 Chat 扩展方案比 ShunCode 的更适合你的目标**
> ——用稳定 API,能上 Marketplace,普通用户装得上。
> 我一开始说"Chat 做不成普通扩展",看过他们代码后确认**那话是错的**。

---

## 第 3 步(可选):支付架构那件事(5 分钟)

如果你还想推进另一个项目的收费功能:

下载 **`支付架构提示词-纯净版.txt`**,粘贴给那个项目的助手。

里面我替你把一件事说死了:

> "我理解这套架构**并没有免除**商户号要求,只是把它从客户端挪到服务端。
> 请确认我的理解对不对,**别让我误以为有捷径**。"

**这很重要**:你之前的说法透露出"ShunCode 好像不需要商户号"的印象——**那是错觉**。
它只是把渠道对接挪进了 Cloudflare Worker,资质该办还得办。带着错误预期去讨论只会浪费更多时间。

---

## 第 4 步(可选):自己验一遍我的工作(10 分钟)

不需要信我,自己跑。在**普通 Windows CMD** 里激活 conda 后,仓库根目录执行:

```
npm install
npm test
npm run audit:docs
npm run verify:btypes
npm run assemble:skeleton-full
npm run diagnose:skeleton
npm run check:release
```

**预期结果**:

| 命令 | 应该看到 |
| --- | --- |
| `npm test` | `# pass 167` / `# fail 0` |
| `npm run audit:docs` | `60 markdown files; 0 finding(s)` |
| `npm run verify:btypes` | `OK - 37 declaration files ... broken control correctly rejected` |
| `npm run diagnose:skeleton` | `errors=0 unresolved=0 layoutResolves=true` |
| `npm run check:release` | **退出码 2**,7 项 BLOCKED ← **这是对的,不是坏了** |

> 💡 每个验证工具都内置了**故意写错的对照**。如果那个对照居然通过了,工具会自己报失败。
> 所以你验证的不只是"它通过了",而是"**它真的在检查**"。

---

## 第 5 步(可选,但价值最高):翻一翻旧备份

找这两样东西中的任何一个,都能明显推进:

| 找什么 | 在哪可能有 | 找到的好处 |
| --- | --- | --- |
| `vscode-main/src/vscode-dts/` 整个目录 | 旧硬盘、备份、Gitee 私有库 | 把我重建的 Chat 声明换成真品,消除不确定性 |
| `bridge-license-worker` 项目 | 你的 Cloudflare 账号 | 服务端支付对接的真实实现 |

**都找不到也没关系**——A 层 + B 层现在已经能完整编译到 0 错误了,
你最初要的"能编辑、能重新编译"**已经达成**。

---

## 不用做的事

- ❌ **不用重装 ShunCode 去翻安装目录**。我查过了,`src/` 和 proposed 声明
  **根本没被打包进去**,重装也找不到。
- ❌ **不用现在就做打包安装器**。那步工作量最大(要搭完整 Code OSS 构建链 +
  Inno Setup),而且只有你确实要发新版本时才值得。
  如果目标只是"看懂当年怎么写的、能改",**现在已经够了**。
- ❌ **不用管那 7 项 BLOCKED 门槛**。它们红着是诚实状态,不是故障。

---

## 如果某一步卡住了

把**实际看到的报错原文**贴给我(不要复述),我来判断是环境问题还是代码问题。

特别是第 4 步:如果 `npm test` 不是 167 通过,先确认 `npm install` 真的跑完了——
`node_modules` 缺失会导致大量误报失败。
