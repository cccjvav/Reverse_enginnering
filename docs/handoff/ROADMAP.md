# 接力路线图：从可复现模块到可发行Windows产品

状态词：**DONE**=列出的范围已有证据；**READY**=可开始，不等于实现；**BLOCKED**=依赖未满足；**PARTIAL**=已有局部成果但不可放行。没有虚构工期。每个阶段输出应带源码SHA、工具版本、命令、退出码、允许/拒绝样例与未验证项。

## 任务顺序与完成标准

| ID / 当前状态 | 前置 | 实际工作与交付 | 通过标准 / 停止条件 |
|---|---|---|---|
| P0 交接与基线 / DONE | 当前仓库 | 本目录、当前源码/证据索引、CMD命令、授权调用图审计；接手者每次仍需重新核对 | 0portable错误、原件/旧overlay不变；新提交CI与历史CI分开写。失败先修基线，不部署 |
| P1 可信文件授权 / READY（审计已做） | P0 | [下一任务详案](NEXT_AUTHORIZATION.md)：宿主策略→Facade→Dispatcher→维护文件工具，限界源转换/provenance/类型与真实虚构文件测试 | 缺失、非true、过期、取消、错owner全部拒绝；源码构建确实包含授权入口；有读/改/移/删和双会话拒绝证据。仅注入一个测试回调不算完整宿主接入 |
| P2 HTTP会话与工具生命周期 / PARTIAL | P1 | 从已有惰性SDK2测试升级为真实虚构文件调用；多会话owner、审批等待、取消、断连、会话删除和停止清理；现代传输分支单独标明 | A会话不可读/取消B任务或复用B审批；未知/空owner拒绝敏感调用；关闭后监听器/待审批/执行任务清理；不得把HTTP bearer等同逐文件许可 |
| P3 宿主与资源契约 / BLOCKED（清单可并行） | 完整隔离Windows材料；P0可先静态分类 | 明确走“公开宿主+文本降级”还是恢复原扩展API；固定Code OSS提交/许可/补丁；清点webview、Git Bash、Agent Host、ripgrep、.node及Electron ABI；按[阶段B](../acceptance/README.md)制作manifest | 原宿主身份或显式改造身份、API与功能降级说明可追溯；目标Electron中原生依赖实测；资源来自清单，不复制整包冒充源码恢复。无法确认身份就继续标候选 |
| P4 真扩展激活 / BLOCKED | P1、P3和可恢复VM | 源码生成实验目录、固定依赖、manifest/资源；在指定载体启动扩展，记录版本、日志、BridgeUI消息与文本回退实际显示 | 是extension.ts实际activate，不是require CJS或空vscode stub；无付费墙且提供方/令牌保护保留；卡片降级有截图对照；失败不继续发布 |
| P5 GUI、MCP和业务回归 / BLOCKED | P2、P4 | [阶段C](../acceptance/MCP.md)：本地真实客户端initialize/list/call、审批允许与拒绝、虚构文件操作、取消/双会话、UI、Skills与重启；外网隧道另行隔离验收 | 记录请求与磁盘前后哈希、预期/实际、清理结果；日志已脱敏；真实令牌不入Git；未运行用NOT_RUN/BLOCKED，不手填PASS |
| P6 源码Windows安装器 / BLOCKED | P3–P5、确定上游构建 | [阶段D](../acceptance/INSTALLER.md)：固定上游构建环境、定制补丁应用、编译/资源构建、user/system安装器与manifest、许可证；干净VM安装/升级/回滚/卸载 | 从源码到EXE全链记录，内嵌扩展哈希匹配，干净VM测试；旧EXE重新打包或overlay不算；签名若未完成须明确未签名，禁止索要私钥 |
| P7 发行与教程闭环 / BLOCKED（教学可持续） | P6；安全门槛均有新证据 | 按证据更新check:release（不能直接改PASS）；区分旧版overlay与新安装器、风险/降级/恢复手册；教程逐行覆盖继续补齐 | 七门槛逐一有可复验来源；非静态技术证据不能由类型数代替；学习覆盖full:false在真正逐行解释完成前保持false |

## 七项BLOCKED对应哪些工作

| 发布门槛 | 对应任务与所缺证据 |
|---|---|
| carrier-identity | P3：当前公开候选不是原定制宿主；若改走新载体须明确身份及支持矩阵 |
| host-chat-api | P3/P4：public文本方案已有实现，仍需真实UI验收及原卡片功能取舍记录 |
| native-runtime | P3/P4：目标Electron实际加载、Git Bash/Agent Host/搜索/资源清单，不仅Node |
| authorization-integration | P1/P2/P5：宿主审批、构建链、真实文件正反向与会话取消，不仅孤立维护单测 |
| http-integration | P2/P5：已有真实SDK+原传输回归；尚缺真实工具/任务/授权/第三方客户端及声明支持的协议路径 |
| real-activation-gui-mcp | P4/P5：完整扩展实际激活、GUI与真实MCP功能验收 |
| source-built-installer | P6：新源码载体编译、扩展打入、EXE和干净VM生命周期 |

“0错误”只能解决候选接口诊断，不会让以上表自动变绿。旧check:release写死BLOCKED是有意安全限制；未来改成证据驱动时必须审查证据格式、被测提交/宿主、真实性和新鲜度，不能只看JSON里一个passed:true。

## 主线之外仍需完成，但不能阻塞P1的事情

- 持续教学：先为P1新增策略/转换/测试逐行讲解，再补原41模块与宿主UI；166文件/31232行是本次修改前快照，不是全部已人工解释。
- Skills归档/进程/网络权限与命令危险性策略独立评审；文件工具有权限不代表shell命令无法绕过。上线前明确禁用未验收能力还是补完整策略。
- 原始依赖锁、原构建配置和准确宿主身份未完全恢复。对恢复不了的部分标“重新实现/公开替代”，不要冒充原作者原始源码。
- 原安装器静态提取自动化继续维护，但不能代替P3–P6；大型提取内容留外部/忽略目录，只提交可重现脚本与小证据。

## 每次工作提交的最小完成定义

1. 不动不可变原件；所有新增alias/转换有源哈希与精确匹配数，匹配失败中止。
2. 修改相关单测、类型、来源核验并覆盖至少一个拒绝/错误路径；更新learn生成物，检查无陈旧内容。
3. 跑完整回归及发布检查，保留“预期NOT_READY”的退出2，不静默吞掉失败。
4. 更新工作日志与STATE.json；记录当前实现停在哪、下一命令是什么，避免留一个“等助手继续”的空泛句子。
5. 推送固定分支并核对CI；远端自动报告更新时先fetch再整合，不force push。
