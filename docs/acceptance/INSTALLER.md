# D阶段：Windows安装器小白验收

**当前没有从恢复工程生成并验证的完整Windows安装器，本阶段全部BLOCKED。** 仓库里的原0.7.4 EXE是来源证据，社区overlay ZIP是固定版本更新补丁，二者都不是新工程安装器。

操作环境仍是普通CMD + conda；只有实际安装GUI要求的步骤才可能需要虚拟机内管理员授权。不要在主力电脑测试安装身份、升级覆盖和卸载行为。

## D00 安装前：资料齐了才能点EXE

先完成 [总手册](README.md) 的B阶段及发布范围内C阶段；技术执行方必须提供：

- 安装器文件名、大小、SHA-256、对应源码提交、构建记录、架构；从可信发布路径取得，而不是同一陌生镜像的“文件+哈希”。
- 用户级还是系统级安装、预计默认安装目录、产品名称/版本、快捷方式名、用户数据位置、更新源和卸载标识。
- 这是独立测试品牌还是要升级原ShunCode；同名不等于应该覆盖同一个安装，版本号高也不证明GUID正确。
- 签名者/签名状态；未签名必须明确说明，不伪造“已签名”。
- 支持哪些升级起点，旧版本是否能读取新数据，回退方案；没有这份说明不自行试降级。

用两类独立快照：

| 快照 | 初始状态 | 用途 |
|---|---|---|
| CLEAN | 干净Windows测试用户，无任何ShunCode | 新装、取消安装、安装身份、卸载 |
| OLD-TEST | 在隔离机安装被批准的旧版本，只含虚构数据 | 同版重装/升级/保留数据/回退 |

不要把装满你真实账号的电脑做成OLD-TEST。每个用例开始前恢复对应快照，单独RUN编号；只在顺序升级场景保留上一步状态。

## D01 下载完整性与签名状态

在验收CMD设置真实路径：

```cmd
set "SETUP=下载的新候选安装器完整路径"
if exist "%SETUP%" (echo SETUP_FOUND) else (echo STOP_NO_SETUP)
certutil -hashfile "%SETUP%" SHA256 > "%RUN%\logs\D01-installer-sha256.txt"
```

如果看到STOP，不继续。打开日志比对发布的64位十六进制SHA，文件大小可在资源管理器→属性中记录。哈希不符立即FAIL，不运行。

资源管理器右键安装器→属性→数字签名（如果有该页），查看签名者与签名详细信息，记录系统显示的有效/无效状态和时间。无数字签名页记“未签名”，不能填“微软已验证”。是否允许未签名实验版必须事先批准；正式签名目标未达到则不能正式放行。

SmartScreen或安全软件拦截：记录提示和文件哈希，停止并调查；本手册不要求关闭杀毒、禁用SmartScreen或一路“仍要运行”。文件存在、哈希相同、签名有效也都不证明功能正确。

## D02 干净新装（CLEAN快照）

1. 确认桌面/任务管理器没有旧ShunCode实例；Windows设置→应用→已安装的应用（Windows10可能叫应用和功能）中没有候选。
2. 在资源管理器双击**D01验证过的候选文件**。不要把SOURCE里的原0.7.4安装器当成它。
3. 逐页记录：产品名、许可、架构/安装范围、目标目录、快捷方式、文件关联、PATH等附加选项；只勾本次批准的项。
4. 用户级安装不应无故要求管理员；系统级安装可能预期需要。与清单不符就取消并FAIL，不尝试绕过权限。
5. 若支持选目录，使用批准的测试路径。不要选择源码目录、旧数据目录、Windows目录或另一产品目录。
6. 等待安装结束，记录完成页。若完成页“立即运行”被默认勾选，首次按计划取消自动运行，先核对安装路径/清单，再做启动验收。

**PASS对照：** 安装正常完成、范围/路径/品牌与清单一致、没有未批准的附加下载/软件/账号登录；应用列表只有预期条目。**FAIL例：** 覆盖原产品、出现两个冲突卸载条目、目标路径错误、用户级安装提权、安装日志报错但仍显示完成。

此项只通过“安装过程”，后面启动和功能还必须独立通过。

## D03 安装后的真实启动与持久化

1. 用安装器创建的快捷方式启动一次，记录它的目标路径（右键→属性）与实际关于页版本；必须是本次安装目录，不是某个旧EXE。
2. 打开RUN\workspace，重复总手册B01—B04：激活、原生运行资产、Chat/Bridge与两个宿主。
3. 在测试应用设置里把Editor Font Size改成一个容易识别的值，例如17；创建虚构文件saved-note.txt。若发布范围要求聊天迁移，建立一条不含秘密的真实测试会话并记录标题。
4. 正常关闭，再用同一快捷方式启动。设置/文件与支持的历史内容保留，没有重复扩展实例或错误日志。
5. 在**虚拟机Windows内部**开始菜单→电源→重启，再验证一次；不要误重启物理主机。未承诺系统开机自启的应用不应擅自自启。

不要用修改conda环境来解决Electron ABI错误。conda Node版本和应用内Node/Electron是两个不同对象。

## D04 同版重装与升级（OLD-TEST快照）

必须分开记录两类：

- 同版重装：相同版本再次安装，目标是修复/幂等性，不是跨版升级。
- 跨版升级：从明确支持的旧构建升级到新构建。旧官方0.7.4、已打社区overlay的0.7.4可能是不同起点，若承诺两者都支持，必须各测一次。

每个起点：

1. 关于页记录旧版本/commit，记录旧安装路径和候选清单要求的身份信息。
2. 放入D03的虚构文件、非默认设置、测试会话；保存必要的前态截图/哈希。不要备份生产密钥。
3. 正常关掉应用再运行新安装器，不手工删旧目录“帮助升级”。
4. 观察是否识别正确目标，用户/系统安装范围是否保持，有没有把另一个测试实例当成升级目标。
5. 完成后确认关于页确为新版本；应用列表/快捷方式数量符合清单。
6. 核对文件和设置、承诺保留的历史；重新执行B/C核心功能，不能仅凭版本号更新就PASS。
7. 检查自动更新源没有把候选退回旧商业版本，也没有未经许可的后台安装。

**PASS：** 支持的迁移数据保持、目标正确、可启动、功能回归通过。**FAIL：** 聊天/设置丢失、登录状态莫名继承错误账号、混用两个版本的资产、旧商店流程复活、重复条目/快捷方式。

如果新候选选择独立产品身份而不支持自动升级，记录为“并存安装”，不能拿它通过“升级旧ShunCode”项；发布说明必须写清。

## D05 取消安装和运行中占用

用CLEAN快照测试取消：安装前点取消，确认应用列表/快捷方式/安装目录无意外残留；若是在复制阶段取消，记录清理结果，必要时保留日志并恢复快照。不要用断电或结束所有系统进程制造失败。

用单独OLD-TEST轮次测试文件占用：保持候选正常打开，再运行安装器，观察是否给出明确关闭/重试提示。选择取消，原程序和虚构数据仍应可用。若清单支持自动关闭，核对先询问且不丢未保存的虚构内容。

对未公开的安装器开关，不猜 `/S`、`/silent`、`/VERYSILENT` 等参数。需要无人值守安装时，由技术执行方为**该实际安装器**给出并验证参数，另立用例，不能套其他软件的命令。

## D06 卸载与保留数据

1. 正常关闭候选与Bridge/隧道。
2. Windows设置→应用，按清单找到**本次候选**，点卸载；核对产品名与安装位置，避免卸载另一个软件。
3. 观察保留/删除用户数据的选项。如果没有说明会删什么，先取消并记录BLOCKED，不猜。
4. 先验证“保留数据”的正常卸载：产品文件/应用条目/快捷方式按承诺移除，RUN里的用户文档与outside夹具不受影响，明确保留的数据位置仍在。
5. 另一个快照轮次再验证“清除候选数据”（仅当产品明确支持）：只删除承诺的候选数据，不删除其他版本/其他Windows用户/真实项目资料。
6. 重装同一候选，核对保留数据是否按承诺恢复；清除数据轮次应为干净状态。发现残留Agent host或隧道进程要记录，不能只看“卸载成功”对话框。

不要运行泛化的 `rmdir /s /q` 或注册表清理命令来让卸载测试看起来干净；手工清理后不能算安装器自身通过。

## D07 回退、中文路径、非管理员及并存

### 回退

优先关闭虚拟机并恢复安装前快照，验证旧测试版本和虚构数据。若产品承诺应用级回退，必须有经过确认的数据格式兼容与恢复步骤；不能对新数据直接安装旧版碰运气。回退成功要重新做最小启动/读取测试。

### 路径/权限矩阵

每项新快照、新RUN，不能仅改截图标题：

| 环境 | 要检查什么 |
|---|---|
| 路径含空格 | 安装、快捷方式、Agent host、PTY/rg查找均正常 |
| 路径含中文 | 同上，日志不乱码、资源定位不失败 |
| 非管理员用户级安装 | 正常安装/更新/卸载，不要求不必要提权 |
| 系统级安装（如果承诺） | 提权符合说明，普通用户能正常启动且数据写入自己的数据目录 |
| 与原版本并存（如果承诺） | 两者快捷方式、安装/数据/更新身份按清单独立，不互相卸载或接管 |
| x64/ARM64等架构 | 只对正式声称支持的架构测试；没有对应机器/VM则BLOCKED，不把x64通过复制给ARM64 |

## D08 最终对照与签字

对照 [RESULTS.csv](RESULTS.csv) 填写每项实际结果。每个PASS都有同一候选提交/哈希与对应证据；更换EXE或重建后，受影响项必须重测，不能沿用旧版本通过记录。

以下任一项成立均不能以“完整恢复安装器”发布：类型/宿主阻断未解决、候选身份不明、必需资产缺失、未授权读写、错误更新源、升级丢数据、卸载误删、尚未执行必测项、只通过CI而没有真实桌面验收。

你只需如实记录“发生了什么”。修类型、修安装脚本、定位ABI或设计数据迁移是技术执行方的工作，不要求你通过关闭安全检查替开发者修复。
