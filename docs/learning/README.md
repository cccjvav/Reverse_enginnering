## 每一课的固定标准

- **目的**：学完能独立完成什么，不是仅知道几个术语。
- **前提**：系统、软件版本、当前目录、需要的文件、不能触碰的文件。
- **动作**：菜单/路径、可复制命令、需要替换的占位符、是否联网/写盘/启动服务。
- **观察**：成功输出范例、检查点、预期失败与意外失败的区别。
- **原理**：输入如何经过每个函数得到输出；类型、语法、数据流、调用者和副作用分开讲。
- **逐行**：真实源文件、版本哈希、行号、逐行解释；同一行有多个字段时分别解释，不写一句“定义属性”糊弄。
- **边界**：哪些测试没有做、哪些缺陷仍存在、什么情况下不能照用。
- **自测**：问题、答案、可重复实验；不要求先猜懂整份工程。

## 教程维护方式

`annotations.json` 保存人工撰写的解释、精确代码行和源文件SHA-256；`tools/build_learning.mjs` 检查它们后生成逐行页与覆盖清单。源代码改了、缺行了或解释为空，检查会失败，避免拿旧教程讲新代码。

```cmd
npm.cmd run learn:check
npm.cmd run learn:lab
```

维护者审核注解后才能用 `npm.cmd run learn:build` 重新生成。生成器**不会自动写出有意义的解释**，也不能证明解释百分之百正确；测试检查的是来源、覆盖与同步，内容仍需人工审阅。

下一次扩充教程必须同步更新覆盖清单，不会把“有标题”“有一段简介”算成该文件逐行完成。

压缩代码有时一行包含大量语法单元。后续会使用单独学习视图拆解并关联原位置，不改原件，也不用“行数占比”冒充工程或学习完成率。
