# 文件读取恢复与安全边界（第二组）

## 本轮交付

新增 `src/read-files.js` 与 `src/workspace-paths.js`，从原 Windows 0.7.4 扩展 bundle 恢复 **22 个声明**，函数体保留，接回 Node 的 fs、fs/promises、crypto、path 依赖。重建包合计 **26 模块 / 152 声明 / 113,420 字节 JS**。

现在可以直接调用 `readFiles(input, context)` 读取文件，返回带行号的内容、分页信息、错误及 SHA-256 版本；`formatReadFilesForModel` 可以生成原模型文本格式。**没有接入 HTTP/MCP 调度器，没有启动服务，也没有改动已有 overlay。** 搜索、图片、补丁写入仍未接齐。

测试只读写系统临时目录中的自建小文件，并在测试结束清理。没有拿用户文件或原证据做修改实验。Windows 使用真实 directory junction；Linux 使用目录符号链接。

## 验证内容

| 类别 | 验证方式 |
|---|---|
| 工作区 | 根目录 realpath、去重、跳过已消失的根；多个已配置根分别查找 |
| 静态路径 | 拒绝 `..` 越界、工作区外绝对路径、同前缀兄弟目录、指向外部的链接 |
| 链接 | 指向内部的目录链接可读；外部链接拒绝；确认过程中替换链接的风险另列下文 |
| 跨平台路径 | Windows 分隔符；POSIX 上优先匹配含反斜杠的真实文件名，再尝试转换分隔符 |
| 内容 | UTF-8 BOM、CRLF、空文件、行范围、EOF、二进制探测、非法 UTF-8 |
| 输出预算 | 单文件行数/字节/token 估算限制，批次输出省略，长行显示截断 |
| 权限/生命周期 | 主机权限回调拒绝、预先取消、确认期间取消、重复请求复用 |
| 版本与格式 | 原始字节哈希（不是显示文本哈希）、行尾变化、模型格式化输出 |
| 差异验证 | 相同临时文件同时交给原 CJS 声明闭包与 ESM 重建模块，逐项比较结果 |

`context.workspaceRoots`、配置和 `checkPermission` 是**主机提供的可信上下文**，不应直接取自远程调用者参数。根目录列表仍需主机确保合法；路径规范化不等于账号授权。输入归一化、Schema 校验、工具参数解析与执行是不同层，不能省掉前面的输入检查。

原读取器为了计算完整版本与总行数，会扫描整个文件；显式只取几行也不是只读取那几行。`maxLineChars` 等主要限制返回内容，**不保证总磁盘 I/O 或长单行缓冲内存有硬上限**。不要把输出预算当作资源隔离。

## 已复现的原版本风险：检查后路径发生替换

可重复实验（所有内容都是临时夹具）：

1. `workspace/slot/a` 原本是内部文件，路径检查通过。
2. 主机权限回调执行期间，把 `slot` 移走，在原位置创建指向工作区外夹具目录的链接/junction。
3. 原代码沿之前保存的路径字符串继续 stat、二进制探测和读取。
4. 原声明与原貌重建模块都返回了外部夹具内容。

这是 **TOCTOU（检查与使用之间的竞态）**，不是重建引入的差异。相应测试明确标注 `KNOWN SNAPSHOT RISK`：测试通过代表成功复现风险，**不是边界安全测试通过**。

### 独立防护候选，不是完整修复

`community/bridge-core/read-files.mjs` 在权限确认后、继续 stat/read 前，再取一次 realpath：

- 与**原先核准的规范根**比较，不把确认后已被换成链接的根目录重新当作可信根。
- 新路径出界则返回 `PATH_OUTSIDE_WORKSPACE`。
- 路径变成另一个内部目标也返回 `PERMISSION_DENIED`，要求重新确认。
- 正常读、范围、版本、权限拒绝和取消行为有对照测试；另有测试限制候选与基线的差异范围。

这个检查点阻止了上述确定性的“等待确认期间替换路径”情形。但检查之后仍有时间窗口，stat、探测和流读取还会按路径分别访问文件。**它不是原子、安全地打开文件的实现，不能宣称抵御恶意并发文件系统修改。** 候选未部署，也未纳入 overlay ZIP。

进一步工作需要考虑复用已验证的文件句柄、明确硬链接/并发修改的威胁模型，以及必要的操作系统隔离；单纯增加一次 realpath 不够。因此这批材料仍是恢复与测试基线，不建议直接暴露给不可信远端调用者。

npm ci --ignore-scripts --no-audit --no-fund

npm test
